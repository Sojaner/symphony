# Optional supporting capabilities: research and recommendation

Checked **2026-09-23**. Advisory research; no runtime behavior changes. Repository baseline supplied by the caller: PR #4, `58040a0`.

## Decision

Require the relevant practice and its evidence at each phase. Prefer a callable, compatible installed capability; otherwise use the short native fallback below. Do not run every suite on every task. Symphony retains model selection, agent depth, dispatch, lifecycle, completion, and shipping authority.

Presence has three distinct meanings: advertised by this session, readable/callable now, and successfully used for this phase. A cache directory, plugin name, or previous session's snapshot proves none of the latter two. Resolve the exact advertised skill name and source before reading it; resolve tools from the current tool inventory. Record an absent, disabled, inaccessible, failed, or incompatible capability honestly instead of treating all cases as uninstalled. Refresh after provider/session changes and actual lookup failures.

## Discovery and invocation by host

**Codex:** use the session's advertised skill names/paths and read the selected `SKILL.md` plus required references. Explicit CLI/IDE invocation uses `$skill`; plugin names are the actual catalog names, not translated Claude commands. The official docs say large inventories may omit skills from the initial list: missing from that list means unknown until available discovery is exhausted, not necessarily uninstalled. Do not invent a universal Skill tool. [S7]

**Claude Code:** plugins expose `/plugin-name:skill-name`; invoke through the available Skill mechanism only when enabled and model-invocable. `disable-model-invocation`, `skillOverrides`, permissions and installation scope can prevent use. A readable cache copy does not override those controls. [S8]

Resolve one implementation of duplicate skills from current host metadata; do not concatenate variants. This session advertises CE 3.28.2, Matt Pocock 1.2.3, Ponytail 4.10.0 and another Ponytail bundle 2.0.0. It advertises Codebase Memory tools. Superpowers and Context7 were not advertised to this researcher; their sources establish practices, not availability here.

## Enforcement and notification

Extend existing work packets/returns with a compact per-applicable-phase record: selected exact capability/source (or native), availability reason, practice, and evidence references. Missing evidence must produce an explicit incomplete/exception result, not a success claim. Reuse CE evidence when available. Do not create a second scheduler, copy entire skill suites, scrape all plugin caches, or put network discovery inside hooks.

Separate **host-observed** calls/results from **agent-reported** compliance. An invocation proves loading, not faithful execution; a return marker proves a report exists, not that its claims are true. A lead must inspect artifacts and verify the checks within its authority. Hooks can validate required records and correlate supported events, but cannot certify semantic design quality or reconstruct a red test from a green final diff.

Claude `PreToolUse` can reject an invalid Agent call before execution. Preserve Symphony's documented post-spawn detection limit for its currently supported Codex collaboration path; `SubagentStart` cannot cancel launch. **Version uncertainty:** current Codex documentation now advertises `PreToolUse` for ordinary local `spawn_agent` (alias `Agent`) while allowing specialized paths to opt out. Therefore do not claim that all Codex versions lack pre-spawn hooks; upgrading Symphony's guarantee requires a real-host smoke for the exact provider path. [S9]

If an installed skill introduces independent model elevation, engines, agents, approvals or shipping that cannot honor the packet, classify it as incompatible for that phase and use the native fallback. CE caller modes alone do not disable those features. Existing user instructions take precedence; do not reopen an already settled user choice merely because a supporting workflow normally asks it. [S2, S6]

Reuse the existing **at-most-once per project/Symphony-version** recommendation cadence. Only notify for an applicable capability with a concrete benefit over the fallback. Aggregate material gaps into one short notice: missing capability, affected phase, benefit, current fallback, official installation reference. Distinguish disabled/broken/incompatible from absent; do not suggest reinstalling a working but incompatible workflow. No auto-install and no delayed startup.
